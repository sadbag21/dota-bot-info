# Запуск, логи и остановка

Бот выводит структурированные текстовые логи в stderr: уровень, событие,
команду, ID чата/пользователя и длительность обработки. Текст входящих сообщений
целиком не записывается. Сетевые ошибки Telegram выводятся без URL с токеном.

Необязательная настройка в `.env` или переменных окружения:

```dotenv
LOG_LEVEL=INFO
```

Поддерживаются DEBUG, INFO, WARN и ERROR. По умолчанию — INFO.
DEBUG добавляет события запросов с account_id / match_id.
Ошибка конфигурации завершает запуск с ненулевым кодом.

Выбранные игроки загружаются из `DATA_DIR/player-selections.json` до подключения
к Telegram. По умолчанию каталог — `data` относительно рабочей папки;
в Docker — `/data` с именованным томом. Повреждённый файл останавливает запуск
без перезаписи. При ошибке сохранения нового выбора бот сообщает об этом,
а прежний выбор продолжает работать. Подробнее: [STORAGE.md](STORAGE.md).

Для остановки нажмите Ctrl+C в терминале. На сервере поддерживается SIGTERM.
Бот отменяет текущие HTTP-запросы Telegram и OpenDota, прекращает обработку
обновлений, закрывает простаивающие соединения и пишет `Bot stopped`.
Активная команда при остановке может остаться без ответа — запрос отменяется.
Принудительное завершение процесса средствами ОС не гарантирует очистку.

Получение обновлений выполняется последовательно. После сетевой ошибки
Telegram повторная попытка происходит через 3 секунды; ожидание тоже
прерывается сигналом остановки. Тайм-аут HTTP Telegram — 40 секунд при
long polling 30 секунд.

Проверка без внешних API:

```powershell
$env:RUN_OPENDOTA_TESTS="0"
go test ./... -count=1
go vet ./...
```
