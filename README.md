# Dota Bot Info

Telegram-бот на Go для просмотра игроков и матчей Dota 2 через
[OpenDota API](https://www.opendota.com/). Поддерживает анализ Impact Score,
навигацию inline-кнопками и запуск в Docker.

Первый релиз: [v0.1.0](https://github.com/sadbag21/dota-bot-info/releases/tag/v0.1.0).
Для запуска именно этой версии выбери тег `v0.1.0` или скачай архив исходников
на странице релиза, затем следуй инструкциям ниже.

## Возможности

- Профиль игрока: ник, ранг, место в leaderboard, победы, поражения и winrate.
- Последние матчи, популярные герои и расширенная статистика игрока.
- Мета героев Immortal по пяти позициям через STRATZ, с учётом актуального патча Valve.
- Подробности матча и оценка вклада игроков — Impact Score.
- Кнопки для переходов между профилем, матчами, героями и статистикой.
- Сохранение выбранного игрока между перезапусками, отдельно на пользователя и чат.
- Проверка Dota ID и Match ID до обращения к OpenDota.
- Понятные ответы при отсутствии данных, превышении лимита, тайм-ауте и сбоях API.
- Ограниченный TTL-кэш, структурированные логи и отмена запросов при остановке.
- Общий лимит команд статистики и кнопок: до 5 подряд, восстановление одного запроса за 3 секунды.

## Команды

| Команда | Результат |
| --- | --- |
| `/start` | Приветствие и основные команды |
| `/help` | Полная справка |
| `/meta [1–5]` | Мета героев: выбрать позицию или сразу показать топ |
| `/player [Dota ID]` | Выбрать игрока или показать выбранного |
| `/matches [Dota ID]` | Последние матчи |
| `/heroes [Dota ID]` | Популярные герои |
| `/stats [Dota ID]` | Расширенная статистика |
| `/match <Match ID>` | Подробности матча |
| `/impact <Match ID>` | Оценка вклада игроков |

Примеры:

```text
/player 1677175114
/match 8983647546
```

Под ответами об игроке есть кнопки «Матчи», «Герои», «Статистика» и «Профиль».
Под ответами о матче — «Impact», «Матч» и ссылка на OpenDota. Кнопки передают
нужный ID автоматически. После успешного `/player ID` команды `/player`,
`/matches`, `/heroes` и `/stats` работают без ID. Выбор хранится отдельно
для каждого Telegram-пользователя в каждом чате и сохраняется между перезапусками.
Явный ID в `/matches`, `/heroes` или `/stats` действует только для этого запроса;
чтобы сменить выбранного игрока, используй `/player ID` или кнопку «Профиль».
Неудачный запрос профиля сохраняет прежний выбор. `/match` и `/impact` требуют Match ID.

Impact Score — собственная эвристическая оценка проекта, а не официальный
рейтинг Valve. Она учитывает боевые показатели, экономику, поддержку команды
и результат матча. Полнота анализа зависит от доступных данных OpenDota.

## Быстрый запуск на Windows

Для `/meta` добавь `STRATZ_API_TOKEN` в `.env` (токен выдаётся на
[STRATZ API](https://stratz.com/api)). Без него остальные команды работают.
Мета использует Ranked All Pick, ранг Immortal и последние 7 полных дней
в пределах текущего патча. День выхода патча исключается. Кэш — до часа;
номер патча проверяется у Valve каждые 15 минут при запросах.
Подробнее о выборке и ранжировании: [META.md](META.md).

Для запуска из исходников нужен Go 1.27 или новее, совместимый с `go.mod`.
Для контейнера нужен работающий Docker Desktop в режиме Linux containers;
локальная установка Go для сборки Docker-образа не требуется.

Все команды ниже выполняются из папки проекта.

1. Если `.env` ещё нет, скопируй `.env.example` в `.env`.
2. В `.env` укажи токен своего бота от BotFather.
3. Выбери один способ запуска ниже.

```dotenv
TELEGRAM_BOT_TOKEN=токен_от_BotFather
LOG_LEVEL=INFO
```

Из исходников:

```powershell
go run ./cmd/bot
```

Через Docker — сборка и первый запуск с выводом логов в терминал:

```powershell
docker build -t dota-bot-info:local .
docker run --rm --name dota-bot-info --env-file .env -e DATA_DIR=/data --mount type=volume,source=dota-bot-data,target=/data dota-bot-info:local
```

Останови копию бота в GoLand перед запуском контейнера с тем же токеном.
Если контейнер с именем `dota-bot-info` уже создан, используй команды управления
из [DOCKER.md](DOCKER.md), а не создавай второй с тем же именем.

Ctrl+C останавливает запуск в терминале. Фоновый запуск, просмотр логов,
остановка и обновление контейнера описаны в [DOCKER.md](DOCKER.md).
Бот на локальном ПК доступен, пока компьютер и Docker работают.

## Конфигурация

Лимит статистики действует на Telegram-пользователя во всех чатах.
При превышении бот сообщает время ожидания; повторные текстовые предупреждения
появляются не чаще раза в 5 секунд. Кнопки отвечают всплывающим уведомлением.
`/start`, `/help` и меню `/meta` без позиции доступны без ожидания.
Подробнее: [RATE_LIMIT.md](RATE_LIMIT.md).

| Переменная | Значение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Обязательный токен Telegram-бота |
| `STRATZ_API_TOKEN` | Необязательный токен для `/meta` |
| `DATA_DIR` | Каталог выбранных игроков: `data` локально, `/data` в Docker-образе |
| `LOG_LEVEL` | `DEBUG`, `INFO`, `WARN`, `ERROR`; по умолчанию `INFO` |
| `RUN_OPENDOTA_TESTS` | `1` включает внешние тесты; для обычной работы не нужна |

`.env` исключён из Git и Docker-образа. При запуске контейнера его значения
передаются через `--env-file`. Подробности логов и остановки: [RUNNING.md](RUNNING.md).

Выбранные игроки записываются в `DATA_DIR/player-selections.json`. Каталог
`data/` исключён из Git. В Docker используй именованный том `dota-bot-data`,
как в примере выше: он сохраняет выбор после пересоздания контейнера.
Подробности: [STORAGE.md](STORAGE.md).

## Кэш

| Данные | Срок хранения |
| --- | --- |
| Профиль, победы/поражения, герои игрока, общая статистика | 2 минуты |
| Последние матчи | 45 секунд |
| Подробности матча | 10 минут |

Лимиты — 512 записей и 16 МиБ сериализованных данных. Ошибки не сохраняются;
после перезапуска кэш пуст. Подробнее: [CACHE.md](CACHE.md).

## Тесты и CI

Обычная проверка без запросов к внешним API:

```powershell
$env:RUN_OPENDOTA_TESTS="0"
go test ./... -count=1
go vet ./...
```

HTTP contract/integration tests используют CUTE и настоящий OpenDota:

```powershell
$env:RUN_OPENDOTA_TESTS="1"
try {
    go test ./tests/opendota -v -count=1
} finally {
    $env:RUN_OPENDOTA_TESTS="0"
}
```

Эти проверки зависят от доступности и лимитов API. Отчёты в
`tests/opendota/allure-results/` не коммитятся.

В GitHub Actions настроены отдельные jobs `Unit Tests` и `OpenDota API Tests`.
Сбои внешних тестов допускаются через `continue-on-error`.
Docker-сборка также запускает unit-тесты и `go vet`.

## Структура проекта

```text
cmd/bot              запуск, конфигурация и сигналы остановки
internal/bot         Telegram-команды, кнопки и сообщения об ошибках
internal/service     обработка статистики и Impact Score
internal/dota        HTTP-клиент OpenDota, модели, ошибки и кэш
internal/meta        STRATZ, патчи Valve, выборка и ранжирование меты
internal/config      загрузка переменных окружения
pkg/formatter        форматирование Telegram HTML
tests/opendota       внешние HTTP-тесты
```

История возможностей: [CHANGELOG.md](CHANGELOG.md).
